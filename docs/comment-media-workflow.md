# 댓글의 원문·미디어 검수

내 글 대댓글과 타인 원글 댓글은 같은 원자료 검증과 게시 직전 검수 게이트를 사용한다. Codex가 문맥·미디어를 확인하고 Gemini는 Codex가 확인한 관찰을 받아 한국어 댓글을 작성한다. Gemini에 사진·영상 원본을 업로드하지 않는다.

1. X 원문 API에서 본문과 모든 사진·영상, 인용 미디어를 확보한다. 내 글의 이미지 사연은 local story queue의 실제 게시된 후속 이미지도 함께 확인한다. 계정명 대소문자가 달라도 status ID로 연결한다.
   댓글 본문은 독립 본문 API와 ID·작성자를 대조한다. 한쪽 본문이 다른 쪽의 앞부분이면 긴 본문을 사용하고, 서로 다른 내용이거나 독립 확인이 실패하면 보류한다. `is_note_tweet=false`도 전문 보장이 아니다. 원문 API가 목록 중간에서 잘렸다는 사실을 실제 작성자가 거기서 글을 끝냈다는 의미로 쓰지 않는다.
   YouTube 영상 링크는 X 첨부가 없다는 이유로 텍스트 전용 글로 취급하지 않는다. 현재 자동 수집기는 YouTube 원본을 검수 자료로 가져오지 않으므로 shorts/watch/짧은 영상 링크 등이 본문·부모·인용에 있으면 생성과 게시 직전 수집에서 보류한다. 채널 주소나 일반 웹 링크 전체를 금지하는 규칙은 아니다. 감독자가 연결된 원본을 별도로 확인해 기존 댓글을 판정할 수 있지만, 그 수동 확인으로 자동 게시 게이트를 우회하지 않는다.
2. 사진 원본, 영상의 0.5초 간격 연속 프레임 시트와 마지막 프레임을 Codex에 제공한다. 영상에 음성 스트림이 있으면 로컬 whisper-cli로 전사한다. 프레임 샘플과 기계 전사로 확인했다는 한계를 기록하며 전체 영상을 직접 재생·청취했다고 주장하지 않는다.
3. Codex가 각 미디어의 구체 관찰, 영상 순서, 음성 확인 상태, 불확실성을 구조화한다. 확인 실패가 하나라도 있으면 보류한다. 짧은 핵심 동작이 샘플 사이에 빠지거나 전사 의미를 확정할 수 없는 영상도 보류한다.
4. Gemini는 원문과 검증된 관찰 기록으로 댓글을 작성한다. 내 글 대댓글은 원글 작성자 관점, 타인 글 댓글은 독자 관점이다.
   작성 입력은 검증된 원문 전문·게시 시각·관찰·영상 순서·음성 확인 상태·불확실성을 전달한다. Gemini가 받지 않는 원본 파일 경로나 Codex의 시각 검사 지시는 작성 입력에서 제외한다. 원자료의 연결 검증과 게시 직전 Codex 검수는 그대로 유지한다.
5. 게시 직전 최신 원문과 미디어를 다시 확보하고 Codex가 실제 미디어와 최종 댓글을 독립 대조한다. 원문 근거, 미디어 확인, 발화자 관점, 상대의 발화 의도에 대한 직접 응답이 모두 통과해야 게시한다. 이전 큐의 댓글도 이 게이트를 거친다.
6. 2026-10-28 사용자 지시에 따라 실제 댓글·대댓글 작성은 기존 격리 headless X writer를 사용한다. 지정 과즙루피 headed Chrome 9224는 인증 원본과 직접 감독 검수·삭제에 유지한다. writer에서 @terafabXai 계정을 매번 확인한 뒤 게시하고, 게시 후 본문·작성자·parent status ID를 검증해 기존 댓글 이력에 기록한다. 작업 탭과 원본 다운로드를 정리하며 감사 JSON·검수 응답은 보존한다.

`잘 보고갑니다`에 원글 상황을 다시 평하는 대댓글은 원글의 단어와 관련 있더라도 직접 응답 실패다. 높은 Gemini 점수는 Codex의 최종 문맥 실패를 무시할 수 없다.

2026-10-28 말투 개선은 `lib/comment-speech.js`에서 생성·재작성·최종 검수에 공통 적용한다. 최소 글자 수를 요구하지 않고, 문맥상 의미가 통하는 짧은 생략구·반문을 허용한다. 기본 초안은 `~네요/~군요` 감상형 종결을 피하고, 장면 요약에 평가를 붙이는 구조도 검수한다. 어미 치환이나 `ㅋㅋ` 일괄 추가는 하지 않는다. 최근 실제 자동댓글 12개를 반복 방지 자료로 전달하되 새 원문의 사실 근거로 쓰지 않는다. 홈 대기 큐의 말투 버전이 오래되면 원문 근거로 새 후보를 생성한 뒤 재심사한다. 새 말투 통과가 원문·미디어·발화자·시점 검증을 대신하지 않는다. 별도의 게시 후 감독 자동화 설정은 변경하지 않는다.

2026-10-29 실게시 비교에서 프롬프트만으로는 `~네요ㅋㅋ`로 되돌아오는 문제가 남아 v5 자동 초안은 `~네요/~군요` 종결을 재작성 대상으로 강제한다. 뒤에 웃음이나 문장부호를 붙여도 통과하지 않으며, 재작성 후에도 남으면 게시하지 않는다. 문장을 정규식으로 고치지 않는다. 버전이 지정된 새 자동 초안에 적용하며 사용자가 직접 지정한 수동 문장은 별도다. 게시 직전 원문·미디어 검수에도 같은 제한을 적용해 모델의 높은 점수만으로 우회하지 못하게 한다.

v6에서는 짧은 직접 반응을 자연스럽다고 설명하면서도 낮은 점수로 재작성시키는 모순을 보완했다. 문맥·구체성은 키워드 반복량보다 상대의 의도에 정확히 답하는지 평가하며, 감점할 때 실제 결함을 설명하도록 한다. 기존 통과 점수와 원문·미디어·시점·발화자·대상 정책 검수는 유지한다. 자동 생성은 여전히 편차가 있으므로 어미 제한 통과만으로 전체 문체 개선이 입증됐다고 보지 않는다.

Codex 최종 검수 프롬프트의 첫 줄 `Codex의 읽기 전용 X 댓글 게시 직전`은 실행기의 JSON 스키마 구분자다. 말투·최근 댓글 지침을 그 앞에 넣지 않는다. 그렇지 않으면 문맥 분석 스키마가 선택되어 필수 게시 판정값이 누락된다. 실제 프롬프트와 스키마를 연결한 회귀 테스트로 검증한다.

구현은 `lib/comment-media-context.js`와 `mirror_server.js`의 `analyzeCommentSourceWithMedia`, `verifyCommentMediaBeforePublication`, `postTerafabxReply`에 있다. 수동 검수는 `POST /api/terafabx/comment-media-check`로 요청한다. `targetUrl`, 필요시 `rootPostUrl`을 전달하며 기본은 비게시 검수다. `publish: true`는 실제 댓글 게시를 요청하므로 수동 게시 권한이 있을 때만 사용한다. 기존 게시 대상은 이력으로 중복을 차단한다.

기본 의존성은 Codex CLI, ffmpeg/ffprobe, whisper-cli와 `.data/models/ggml-small.bin`이다. `CODEX_BIN`, `TERAFABX_COMMENT_WHISPER_MODEL`로 위치를 지정할 수 있다. 안전한 처리 상한은 원본 미디어 10개, 파일당 80MB, 영상 90초, 시각 검수 이미지 50장이다. 상한을 넘는 자료는 일부만 확인한 뒤 게시하지 않고 수동 검수 대상으로 보류한다.

검수 근거는 `.data/comment-media-context`에, 실검증 증거는 `.data/comment-workflow-e2e`에 저장한다. 영상 음성 전사는 오류가 있을 수 있으므로 시각 자료·자막과 충돌하는 전사를 사실로 채택하지 않는다.

수동 감독의 교차 전사에는 `.data/models/ggml-large-v3-turbo-q5_0.bin`도 사용할 수 있다. 기본 자동 전사 모델을 바꾼 것은 아니다. 소형 모델이 음악 태그만 반환한 자료는 추가 모델로 필요한 구간과 전체 음성을 대조하고, 확인된 발화 언어가 자동 감지와 다르면 그 언어를 명시해 재전사한다. 음악으로 시작하는 영상의 전체 자동 언어 감지가 후반 한국어 내레이션을 놓칠 수 있다. 더 큰 모델의 반복 문구나 음향 분류 수치도 실제 대사·가사 확인을 대신하지 않으며, 불명확한 부분은 계속 보류한다. 모델 파일은 원 배포처의 SHA-256과 대조하고 원자료를 외부 전사 서비스에 업로드하지 않는다.
