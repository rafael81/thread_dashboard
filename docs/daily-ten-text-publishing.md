## AAGAG 핵심 이미지

이미지는 선택 사항이다. 원문 핵심 상황을 보여주면서 “왜?”가 남아 답글을 읽게 하는 원본 이미지 한 장만 첫 글에 추가한다. 이미지 안의 자막·표정·배경도 직접 읽고, 반전·정답·해결이 담겼거나 전체 원문을 한 장으로 옮긴 이미지는 붙이지 않는다. 창작에 출처 이미지를 섞지 않는다. 이미지가 적합하지 않으면 텍스트 타래로 게시한다.

## 창작 AI 삽화

AAGAG 원본짤 대신 생성 이미지를 끼우지 않는다. 기본 imagegen 도구로 제작하고 생성 파일을 해당 원고 폴더에 복사한다. `image-prompt.txt`에 최종 프롬프트를, `source.json.rootMedia`에 `kind:"ai_generated"`, 파일, sha256, `generation:{tool,promptFile,generatedAt}`, `review:{passed,spoilsResolution:false,reason,viewedAt,aiDisclosureVisible:false}`를 남긴다.

추가 사용자 지시 “삽화는 예전 내 ai 삽화 스타일 … 그거 스타일로 하고 워터마크도 추가”를 적용한다. 기준은 `.data/story-drafts/2026-10-25/workplace-reversal/art-original.png`와 `life-comedy/art-original.png`에서 직접 확인한 성인 인물의 선명한 선화·셀 명암·따뜻한 색감의 2D 애니풍이다. 기준 그림을 스타일 참조로 입력하고 새 장면을 그린다. 이미지 오른쪽 하단 안전 여백에 작고 옅은 `@terafabXai` 계정 워터마크를 넣고 정확한 철자를 직접 확인한다. 기존 `AI 삽화` 표시 지시는 최신 사용자 요청으로 대체했으며 계정 워터마크만 유지한다. 예전 흰 본문 카드의 중앙0.5% 규칙은 그 카드 형식의 기록이며, 현재 단독 삽화에 흰 본문 영역을 새로 만들지는 않는다. 생성 워터마크의 정확한 불투명도 수치를 보장하지 않는다. `rootMedia.styleReference`, `rootMedia.watermark`와 `review.styleMatched/watermarkVerified`에 근거를 남긴다. 이전 화풍 교체본 `root-ai-anime-watermark.png`와 당시 프롬프트 `image-prompt-anime.txt`는 보존하며, 현재 업로드에는 아래 최신 표기 정책의 파일을 사용한다.

이미지를 실제로 열고 인물별 팔·손 개수, 어깨부터 손까지의 연결, 손가락·물건 쥐기, 결말 누출과 표기를 직접 검수한다. `image-review.json`은 `docs/terafabxai-daily-task.md`의 version1 검수 형식을 따르며 이미지가 바뀌면 해시와 시각 검수를 갱신한다. `lib/daily-story-media-review.js`가 생성 근거·원고 내부 경로·이미지 해시·시각검수 기록·현재 공개 표기 정책·메타데이터 제거·계정 워터마크를 검사한다. 이는 이미지의 인체를 자동 판독하는 검사가 아니다.

최신 사용자 지시 “AI 이미지 메타데이터 제거하고 올려. 그리고 ai제작표시하지마”에 따라 `fictionAiImagePolicy.publicAiLabel=false`를 적용한다. 생성 원본과 내부 `kind=ai_generated`, 프롬프트·도구 기록은 보존한다. `lib/story-upload-image.js`의 `prepareStoryUpload`로 PNG 업로드 사본의 caBX(C2PA)·EXIF·텍스트 메타데이터를 제거하고 디코딩된 픽셀 동일성을 확인한다. 최종 사본을 `rootMedia.file/sha256`에 연결하고 `upload-metadata-review.json`에 제거 항목·원본/최종 해시·픽셀 동일성 근거를 저장한다. 시각검수에는 `aiDisclosureVisible=false`, `image-review.json.checks.ai_label_absent=true`와 워터마크 검증을 기록한다. 게시예정 `2026-11-01/08`은 `root-ai-watermark-only-upload.png`와 `image-prompt-watermark-only.txt`를 사용한다. 이미 게시한 그림과 영수증은 변경하지 않는다. X가 별도로 붙이는 자동 표시는 실제 정상 게시 결과에서 확인하며 파일 수정만으로 제거됐다고 단정하지 않는다.

AI 창작 이미지의 실제 게시 E2E는 다음 해당 슬롯에서 정상 게시한 루트·답글 영수증, X 첨부수1·본문·계정·부모ID·타래 및 대시보드 확인 후에만 `fictionAiImageE2EVerified=true`로 기록한다. 편성·파일 생성·plan-check 통과만으로 게시 완료나 E2E 완료라 하지 않는다.

## 대시보드 연결

2026-10-31 최신 범위 정정 “전체로 적용해”: 1인칭 참여자 화법은 창작과 AAGAG 재구성 모두에 적용한다. 현재 미게시 새 편성24편 중 창작14편의 원글·결말 시점을 재검수하고, AAGAG10편의 원글·결말을 참여자인 나의 말과 행동으로 각색했다. `daily-ten-policy.json.narrativePolicy`와 `narrativePolicyVersion=2026-10-31-all-first-person-v1`을 따른다. 변경 전 원고는 `.data/story-drafts/editorial-all-first-person-2026-10-31/revision-manifest.json`에 보존하며 다시 편성하지 않는다.

“글이 있음”, “사진이 올라옴”, “문자 캡처임” 같은 제삼자 소개를 본문 기본 화법으로 쓰지 않는다. 원글과 답글에서 동일 참여자의 호칭·관계·시점을 유지하고 답글 첫머리에서 원글 의문을 푼다. AAGAG는 원출처 URL과 사건·대화·결말, 농담·가정·합성 이미지라는 맥락을 내부 `sourceAdaptation`에 보존한다. 1인칭 역할 각색은 사용자의 실제 직업·가족·경험 인증이 아니며 원문에 없는 중요한 피해·사실·결말을 추가하지 않는다. 인용 문장 저자도 바꾸지 않는다. 창작12·AAGAG8 및 게시 직전 원문·인기도45분 재확인 규칙은 유지한다.

`lib/daily-story-narrative-review.js`는 두 유형 모두의 참여자 메타데이터와 최종 원글·답글 해시, `first-person-review.json.passed`를 게시/편성 검사에 요구한다. 이미 게시된 글과 영수증은 보존한다. 기존212편은 계속 보류하며, 나중에 재개 지시가 있어도 같은 전체1인칭 검수를 거치기 전에는 게시하지 않는다.

`lib/daily-publishing.js`가 실제 `mirror-history.json`의 daily-ten 이력에 저장된 원고·답글 영수증을 연결한다. 게시됨에는 첫 문장, 전체 첫 글, 전체 답글, 실제 게시 시각, X 원글·답글 링크와 AAGAG 출처를 표시한다. 편성만 된 항목은 게시예정으로 남고 영수증 없는 답글은 완료로 세지 않는다. 기존 212건 보류 정책은 바꾸지 않는다. `.data/story-drafts/daily-ten/lineup.json`은 기존 로컬 디스패처에 주입하지 않는다.

게시예정의 기본 ‘새 편성’ 보기는 daily-ten 원고만 보여주며 ‘전체’에서 기존 항목도 볼 수 있다. 단발 `creative:` 게시도 실제 보관 원고와 답글 영수증을 연결한다. 새 원고의 AAGAG/창작 분류와 결말 답글 완료수는 대시보드에서 별도로 표시한다.


### AAGAG 원문 시작일48시간 확인

기존 사용자 선호(memory #708)에 따라 원문 시작일 `S:` 기준 최근48시간 이내 글만 게시한다. 최근 `E:` 재유통으로 오래된 사건의 나이를 초기화하지 않는다. 게시 직전 `source.originalStartedDate` 또는 더 정확한 `originalStartedAt`과 근거를 저장한다. 날짜만 알면 그 날짜00시부터 계산한 최대 나이도48시간 이내여야 하며, 경계가 불확실하면 원출처 시각을 더 확인한다. 미래 `plan-check`는 게시 직전 재확인을 전제로 허용하지만 실제 게시는 `curationFreshnessPolicy`로 차단한다. 기한을 넘은 미리 편성 후보는 다른 AAGAG로 교체하고 교체 전 원고는 보관한다.
