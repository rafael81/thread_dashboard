## 3. 로컬 예약 등록

- 완성된 사연부터 POST http://127.0.0.1:3131/api/story-schedules 로 등록한다. JSON형식: {"items":[{"id":"YYYY-MM-DD-NN","storyDir":".data/story-drafts/YYYY-MM-DD/NN","operatingDate":"YYYY-MM-DD","scheduledAt":"시간대 포함 ISO"}]}.
- 비어 있는 미래 슬롯만 채운다. API는 @terafabXai 계정을 검증하고 원고·이미지 해시를 큐에 고정한다. 기존 예약을 포함한 하루 15건 상한을 지킨다.
- X 네이티브 예약창을 열지 않는다. 실제 게시와 결말연결은 서버의 15초 디스패처가 수행한다. 이미로컬등록된 항목을 별도로 직접게시/임시저장/네이티브예약하지 않는다.
- HTTP 200의 added/existing과 GET큐의 id,시각,본문,답글,미디어를 대조한다. 큐등록=scheduled, 실제게시완료=posted를 구분한다. completedAt과 rootReceipt/replyReceipts가 있어야 실제완료다.
- 기존 최초로컬E2E 증빙 .data/story-drafts/local-e2e-verification.json을 확인한다. 게시경로를 바꿀 경우 실제 서버→Chrome9224→X 계정으로 E2E를 다시 검증한다. 게시 코드나 설정을 이유 없이 수정하지 않는다.
- needs_review는 전송결과미확인이다. 실제X상태를 확인하기 전 재전송하지 않는다. 이미성공한 본문을 다시올리지 말고 누락된답글만 재개한다. 서버재시작 후30분이넘은 슬롯은 몰아게시하지 않는다.

- 생성 성공이나 사용자의 일괄 게시 승인을 이미지 품질 검수로 간주하지 않는다.

- 이 검사는 시각 검수 기록과 파일의 일치를 확인하는 장치다. 이미지 속 인체를 자동 판정하거나 모든 생성 오류가 없음을 보증하지 않는다.
