최신 지시(2026-10-06): 하루 업로드는 30건으로 변경했다. 새 글 제작은 중단 상태다. productionMode=stopped_by_user 또는 automationEnabled=false이면 새 제작을 시작하지 않는다. 사용자 명시적 제작 재개 승인 전까지 기존 완성 재고의 로컬 게시만 계속한다. 큐레이션이 없는 날은 창작 30건까지 허용한다.

## 1. 실제 상태와 오늘의 부족분 확인

- 한국시간 오늘 날짜 D가 운영일이다. 게시 범위는 D의06:00~D+1의01:00이며, lib/story-schedule.js의 storySlots(D)가 정확히 30개의 슬롯을 만든다.
- GET http://127.0.0.1:3131/api/story-schedules 와 .data/story-drafts/local-queue.json, mirror-history.json, 과거 일일 원고를 대조한다. 오늘 이미 큐에 들어간 사연은 30건에 포함한다. 같은 원고를 날짜만 바꿔 재사용하지 않는다. 게시된 본문과 답글은 별개의 사연으로 세지 않는다.
- 서버가 안 뜨면 로컬 LaunchAgent com.terafabx.mirror-server와 .data/logs/mirror-launch.*를 확인해 복구한다. 기존 서버와 중복 기동하지 않는다.

## 2. 완성 콘텐츠 제작

- 2026-10-08 최신 일일 구성: 총 30편 중 애니풍 15편, 기존 이미지 스타일 15편을 번갈아 섞는다. 캐러셀 사연은 하루 3편이며 하루 30편과 애니풍 15편 안에 포함한다. 캐러셀은 하루 앞·중간·뒤(권장 5·15·25번째)에 분산하고 별도 추가 게시로 세지 않는다. 이 구성 변경만으로 중단된 제작 자동화를 다시 켜지는 않는다.
- 캐러셀도 첫 X 본문에는 짧은 사연 제목을 쓰고 이미지 1장만 올린다. 나머지 3장은 댓글 이미지로 연결하며, 댓글 이미지는 상단 그림 없는 흰 바탕의 38px 텍스트만 사용한다. 댓글 X 본문은 빈 문자열이다. 새로운 제목·이미지 구성은 업로드 전에 미리보기로 보여주고 승인받는다. 서로 다른 사연은 최소 1분 간격으로 게시한다.
- 가족·직장·연애·친구·이웃 소재와 감동·유머·갈등·반전을 다양하게 섞어 새로운 완결 사연을 쓴다. 같은 결말에 이름/직업만 바꾸지 않는다. 창작은 실제 제보라고 주장하지 않으며 source.json type=fiction으로 기록한다.
- 큐레이션은 하루1건, 사실을 검증하고 원문 URL과 자료를 내부source.json에 남긴다. 공개 이미지와 글에는 출처/원문사실요약/편집재배포 라벨을 덧붙이지 않는다. 남의 글을 창작으로 분류하지 않는다.
- 각 사연 폴더는 .data/story-drafts/YYYY-MM-DD/NN/이다. post.txt(제목), body.txt(이미지 도입본문), reply_01.txt(완결답글), story_full.txt, source.json(type=fiction 또는curation, 큐레이션은 source.url 필수), image.png를 실제 완성한다. 원고나 생성프롬프트만 저장하고 제작 완료로 세지 않는다.
- 사용 가능한 이미지 생성 스킬을 먼저 읽어 준수한다. 그림 또는 사진이 위, 흰색바탕 검정 한글 도입이 아래에 있는 기존사연 형식을 따른다. 짧은 제목은 이미지밖 X 게시문구로 둔다. 이미지에 분류 라벨·장식 제목·페이지 번호를 넣지 않는다. 이미지를 직접 열어 한글·가독성·소품·인원·장소를 확인한다. 사용자 지시에 따라 생성 원본은 보관하고 업로드용 PNG 복사본의 C2PA·EXIF·텍스트 메타데이터를 제거한다. 로컬 게시기는 lib/story-upload-image.js로 이 처리를 자동 수행하고 픽셀 동일성을 검증한다. 원본 image.png와 큐 해시는 임의로 바꾸지 않는다. 공개 글에 AI 제작 문구를 덧붙이지 않는다. X의 추후 자동 표시 여부까지 보장하지 않는다.
- 같은 사연/제목/큐레이션URL은 과거 게시·예약을 포함해 중복시키지 않는다.

## 3. 로컬 예약 등록

- 완성된 사연부터 POST http://127.0.0.1:3131/api/story-schedules 로 등록한다. JSON형식: {"items":[{"id":"YYYY-MM-DD-NN","storyDir":".data/story-drafts/YYYY-MM-DD/NN","operatingDate":"YYYY-MM-DD","scheduledAt":"시간대 포함 ISO"}]}.
- 비어 있는 미래 슬롯만 채운다. API는 @terafabXai 계정을 검증하고 원고·이미지 해시를 큐에 고정한다. 30건 모두 생성될 때까지 초기 완성분 등록을 미루지 않는다.
- X 네이티브 예약창을 열지 않는다. 실제 게시와 결말연결은 서버의 15초 디스패처가 수행한다. 이미로컬등록된 항목을 별도로 직접게시/임시저장/네이티브예약하지 않는다.
- HTTP 200의 added/existing과 GET큐의 id,시각,본문,답글,미디어를 대조한다. 큐등록=scheduled, 실제게시완료=posted를 구분한다. completedAt과 rootReceipt/replyReceipts가 있어야 실제완료다.
- 기존 최초로컬E2E 증빙 .data/story-drafts/local-e2e-verification.json을 확인한다. 게시경로를 바꿀 경우 실제 서버→Chrome9224→X 계정으로 E2E를 다시 검증한다. 게시 코드나 설정을 이유 없이 수정하지 않는다.
- needs_review는 전송결과미확인이다. 실제X상태를 확인하기 전 재전송하지 않는다. 이미성공한 본문을 다시올리지 말고 누락된답글만 재개한다. 서버재시작 후30분이넘은 슬롯은 몰아게시하지 않는다.

## 4. 보고와 지속

하루 목표30건에 맞게 실제제작·검수·큐등록을 끝까지 수행한다. 부족하면 남은 원고를 계속 제작한다. 실제 제약으로 완료할 수 없으면 성공 수와 부족분, 원인을 정확하게 기록한다. .data/story-drafts/YYYY-MM-DD/daily-report.json에 창작/큐레이션수,예약수,실제게시수,최초·마지막KST슬롯,실패목록을 저장한다. 사용자에게는 실제 숫자와 필요한 조치만 보고한다. 새 메신저/이메일은 보내지 않는다. 작업탭만 닫고 임시다운로드를 정리하며 기존사용자탭과원본아카이브는 보존한다.
