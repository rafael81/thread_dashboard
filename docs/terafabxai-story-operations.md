# @terafabXai 사연 운영 정책

사용자 최종 확정: 2026-09-28. X 네이티브 예약 대신 로컬 예약으로 운영한다.

- 기존 프로젝트와 .data/story-drafts/를 사용한다.
- 하루 최대 30건을 업로드한다. 큐레이션은 하루 최대 1건이며, 준비된 큐레이션이 없는 날은 창작글 30건을 사용할 수 있다. 새 글 제작은 사용자 중단 지시로 꺼져 있으며 별도 재개 지시 전까지 기존 완성 재고만 사용한다. 결말 답글은 사연 건수에 별도로 포함하지 않는다.
- Asia/Seoul 운영일 D의 06:00부터 D+1의 01:00까지 30개 슬롯. lib/story-schedule.js가 35~40분 간격으로 생성한다.
- 형식: X 게시글 본문의 짧은 사연 제목 + 사진/도입 이미지 1장 → 결말 연결 답글. 이미지에 별도 장식 제목이나 분류 라벨을 추가하지 않는다.
- 공개물에는 출처/원문 사실 요약/편집·재배포 라벨을 넣지 않는다. 내부 source.json에는 원문과 사실 확인 자료를 남긴다. 창작은 fiction으로 기록하며 실제 제보라고 주장하지 않는다.
- 생성 이미지 원본은 보관하고, X 업로드용 PNG 복사본에서 C2PA·EXIF·텍스트 메타데이터를 제거한다. lib/story-upload-image.js가 픽셀이 같은지 검증한 뒤 lib/story-x-publisher.js가 복사본을 업로드한다. 기존 예약분과 새 예약분 모두 게시 직전에 적용하며 임시 복사본은 작업 후 정리한다. 제거 또는 검증 실패 시 원본으로 대신 게시하지 않는다. 본문에 AI 제작 문구를 추가하지 않는다. X의 추후 자동 표시 여부까지 보장하지 않는다.
- 가족·직장·연애·친구·이웃의 구체적인 일상 사연을 다양하게 제작한다. 이름만 바꾼 반복 줄거리를 금지한다.

## 로컬 예약 실행

서버 mirror_server.js:3131의 POST /api/story-schedules에 items 배열을 보낸다. 각 항목은 id, storyDir, operatingDate(YYYY-MM-DD), scheduledAt(시간대 포함 ISO)다. storyDir은 기존 프로젝트의 .data/story-drafts/ 하위이며 post.txt, body.txt, reply_01.txt(추가 번호 가능), image.png, source.json이 완성되어 있어야 한다.

계정 확인 후 본문·답글·이미지 해시를 local-queue.json에 영속 저장한다. 같은 ID 재요청은 멱등적이며 같은 사연/제목/큐레이션 URL, 하루 30건 및 큐레이션 1건 초과를 막는다. 예약 뒤 이미지가 바뀌면 게시하지 않는다.

서버는 15초마다 도래한 항목을 하나씩 처리한다. Chrome 9224 전용 과즙루피 프로필에서 @terafabXai를 확인한 후 실제 X 작성창으로 게시한다. 본문 성공 URL을 즉시 저장하고 그 URL에 결말 답글을 연결한다. X UI가 발생시킨 CreateTweet/CreateNoteTweet 응답에서 계정·본문·미디어 수·부모 게시물 ID를 검증한다. 성공 URL은 mirror-history.json에도 남긴다.

2026-10-07 사용자 요청: 본문과 연결 답글은 한 Chrome 작업 탭과 하나의 게시 세션에서 처리한다. 본문 게시 후 해당 화면의 정확한 게시물 답글 버튼(필요하면 게시 성공 알림의 해당 글 보기 링크)을 사용한다. 각 답글을 열기 전에 200~1000ms의 랜덤 대기를 추가한다. 같은 세션에서 생성한 글을 다시 새 탭으로 열거나 강제 이동하지 않는다. 중단된 사연을 재개할 때만 저장된 부모 글로 최초 이동한다. 모든 답글 처리 또는 오류 발생 후 작업 탭을 닫는다. 이 변경이 X 오류226을 방지한다고 보장하지 않는다.

전송 전 실패만 최대 3회 재시도하며, 본문이 성공했으면 답글부터 재개한다. 클릭 이후 결과가 불확실하거나 전송 중 서버가 재시작되면 needs_review로 두어 중복 전송을 막는다. X 실제 게시 상태 확인 없이 needs_review를 scheduled로 바꾸지 않는다. 30분 넘게 지난 미게시 슬롯은 missed 처리하며 몰아서 게시하지 않는다.

GET /api/story-schedules로 현재 큐를 조회한다. POST /api/story-schedules/run은 이미 도래한 항목 한 건만 처리하며 미래 시각을 무시하지 않는다. 이 API는 로컬 요청만 받는다. 기존 Discovery의 A/B 예약 설정은 별개로 유지한다.

## 반복 제작과 프로세스 유지

Orca 자동화 ID: 3a51af1d-423a-4132-b6c1-daf113864c54. 제작 자동화는 사용자 지시로 비활성화되어 있다. 하루 업로드 수 변경은 제작 재개 승인이 아니다. 재개 승인 시 기존 01:10 KST 제작 시간을 사용할 수 있다. 실행 지시는 docs/terafabxai-daily-task.md를 따른다. 실제 활성화 상태와 E2E 결과는 .data/story-drafts/operations-policy.json 및 증빙을 확인한다.

LaunchAgent com.terafabx.mirror-server는 기존 서버가 3131을 사용하면 대기하고, 포트가 비면 서버를 시작한다. 별도 사용자 서버를 중복 실행하지 않는다. 서버·Chrome·인터넷·로그인이 필요하다. 예약 등록은 게시 성공을 뜻하지 않으며, 본문과 모든 결말 답글의 영수증이 있어야 posted다.

## 2026-10-08 사용자 수정: 이미지 댓글과 게시 간격

- 향후 하루 30편의 구성은 애니풍 15편과 기존 이미지 스타일 15편이다. 하루 캐러셀 3편은 총 30편 및 애니풍 15편 안에 포함한다. 스타일을 번갈아 섞고 캐러셀은 하루 앞·중간·뒤에 분산한다. machine policy는 operations-policy.json의 dailyContentMix다. 기존 예약 이미지 교체는 별도 제작·미리보기 승인이 필요하며, 정책 저장을 실제 예약분 교체 완료로 기록하지 않는다.
- 첫 X 게시글은 짧은 사연 제목을 본문에 쓰고 이미지 1장만 첨부한다. 이미지 안 제목을 추가하라는 뜻이 아니다.
- 이어지는 댓글은 그림을 제거한 흰 바탕의 38px 텍스트 이미지로 올린다. 댓글의 X 본문은 비워 둔다.
- thread.json의 root.text는 공개 제목이며, 비어 있는 기존 manifest는 post.txt 제목을 사용한다. replies의 text는 빈 문자열이다.
- 새로 만들거나 수정한 사연은 제목과 이미지 구성을 함께 미리 보여주고 승인받는다. 삭제한 사연은 자동 재게시하지 않는다.
- 여러 사연을 연속 게시할 때 이전 사연 완료부터 다음 사연 시작까지 최소 60초를 둔다. 서버 재시작 후에도 저장된 완료 시각으로 간격을 지킨다. 같은 사연의 이어지는 댓글은 기존 200~1000ms 대기로 연결한다.
- 제목 복원과 60초 간격 변경은 자동 테스트 18개 통과 및 서버 반영. 이 변경 후 실제 게시 E2E는 아직 미검증이며 다음 승인된 게시에서 확인해야 한다.
