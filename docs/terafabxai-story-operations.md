## 로컬 예약 실행

서버 mirror_server.js:3131의 POST /api/story-schedules에 items 배열을 보낸다. 각 항목은 id, storyDir, operatingDate(YYYY-MM-DD), scheduledAt(시간대 포함 ISO)다. storyDir은 기존 프로젝트의 .data/story-drafts/ 하위이며 post.txt, body.txt, reply_01.txt(추가 번호 가능), image.png, source.json이 완성되어 있어야 한다.

계정 확인 후 본문·답글·이미지 해시를 local-queue.json에 영속 저장한다. 같은 ID 재요청은 멱등적이며 같은 사연/제목/큐레이션 URL, 하루 15건 및 큐레이션 3건 초과를 막는다. 예약 뒤 이미지가 바뀌면 게시하지 않는다.

서버는 15초마다 도래한 항목을 하나씩 처리한다. Chrome 9224 전용 과즙루피 프로필에서 @terafabXai를 확인한 후 실제 X 작성창으로 게시한다. 본문 성공 URL을 즉시 저장하고 그 URL에 결말 답글을 연결한다. X UI가 발생시킨 CreateTweet/CreateNoteTweet 응답에서 계정·본문·미디어 수·부모 게시물 ID를 검증한다. 성공 URL은 mirror-history.json에도 남긴다.

2026-10-07 사용자 요청: 본문과 연결 답글은 한 Chrome 작업 탭과 하나의 게시 세션에서 처리한다. 본문 게시 후 해당 화면의 정확한 게시물 답글 버튼(필요하면 게시 성공 알림의 해당 글 보기 링크)을 사용한다. 각 답글을 열기 전에 200~1000ms의 랜덤 대기를 추가한다. 같은 세션에서 생성한 글을 다시 새 탭으로 열거나 강제 이동하지 않는다. 중단된 사연을 재개할 때만 저장된 부모 글로 최초 이동한다. 모든 답글 처리 또는 오류 발생 후 작업 탭을 닫는다. 이 변경이 X 오류226을 방지한다고 보장하지 않는다.

전송 전 실패만 최대 3회 재시도하며, 본문이 성공했으면 답글부터 재개한다. 클릭 이후 결과가 불확실하거나 전송 중 서버가 재시작되면 needs_review로 두어 중복 전송을 막는다. X 실제 게시 상태 확인 없이 needs_review를 scheduled로 바꾸지 않는다. 30분 넘게 지난 미게시 슬롯은 missed 처리하며 몰아서 게시하지 않는다.

## 관리 화면의 사연 분류
